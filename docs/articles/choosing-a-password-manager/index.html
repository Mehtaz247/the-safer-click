Choosing a Password Manager Without a 40-Feature Spreadsheet

Start with the manager you will actually use on every device. Then check five things: generation, autofill, MFA, recovery, and a safe way out.

Published September 15, 2026Updated September 15, 20267 min read

The short version

  • A reputable password manager built into your browser or device is a reasonable starting point if it works everywhere you sign in.
  • Require a password generator, site-matched autofill, and multifactor authentication for the vault account.
  • Understand recovery before moving your passwords: who can restore access, what proof is required, and what happens if your recovery material is lost.
  • Check that you can leave later. Export is useful for migration, but exported password files may be unencrypted and must be handled carefully.

Choose for the accounts and devices you really use

The most secure-looking manager is not useful if it is missing on the phone, browser, or computer where you need to sign in. Start by listing those devices and whether they are personal, shared, or managed by work or school. The UK National Cyber Security Centre says platform support matters because gaps can push people back to insecure workarounds.

If your personal devices use the same browser or operating-system ecosystem, its built-in manager may be the simplest dependable choice. NCSC guidance says saving passwords in a browser or device manager is safe on your own devices, provided the device and account are protected and kept updated. A reputable standalone manager becomes more useful when you mix operating systems or browsers, need deliberate sharing features, or want less dependence on one device vendor.

Keep this boundary

Never save passwords in a browser profile on a library, school lab, hotel, or other public computer. On a shared home device, use separate protected user profiles before enabling password saving.

Filter one: can it create and fill unique passwords?

The core job is not storing the passwords you already reuse. It is making a different random password for each account and filling it without asking you to memorize it. NIST says password managers help people use stronger passwords, particularly when they include password generators, and NCSC guidance highlights generation and autofill as central benefits.

Try the manager on a few ordinary accounts before migrating everything. Confirm that it offers to generate a password during signup and password changes, saves the correct username and site, and fills only on the matching domain. NCSC's buyer guidance says a manager should offer credentials only to the site they were saved for—not expose the whole vault to a page you visit.

  1. Install the official app or extension from the vendor, browser store, or device app store.
  2. Create two test entries for low-stakes accounts you already control.
  3. Generate a different password for each and confirm both save correctly.
  4. Visit each site from a bookmark and check that the manager offers only the matching login.
  5. Confirm the same entries are available on every personal device you plan to use.

Filter two: can you protect the vault itself?

A vault concentrates valuable credentials, so its own login deserves stronger protection than an ordinary account. NIST recommends choosing a manager that supports multifactor authentication. NCSC guidance likewise recommends two-step verification for a password-manager account and says cloud-sync managers should support it.

Use a long, unique primary passphrase that you do not use anywhere else, then turn on the strongest MFA method the manager and your devices support. Keep the device screen lock enabled and keep the manager, browser, and operating system updated. Biometric unlock can make daily use easier, but it does not remove the need to understand the primary password and recovery path.

Filter three: does recovery match your risk?

Recovery is a tradeoff, not a box to tick. A design in which only you hold the decryption secret can prevent the provider from reading your vault, but losing that secret may make the vault unrecoverable. A provider-assisted, administrator, family, or trusted-contact recovery route may reduce lockout risk while creating another route that must be protected.

Before importing passwords, read the manager's current recovery documentation. Ask who can start recovery, whether recovery reveals existing vault contents or only restores the account, how long it takes, and which recovery code or device must survive a lost phone. CISA advises choosing a recovery method you are comfortable with; NCSC advises understanding both how recovery works and who has that ability. Store any emergency or recovery code separately from the vault and the device it may need to recover.

Filter four: can you assess the vendor and leave later?

Look for plain documentation about encrypted storage, supported platforms, security updates, vulnerability reporting, and how the company responds when a flaw or incident is found. NCSC's buyer guide recommends checking a vendor's disclosure policy, update process, and past response to vulnerabilities. No history proves a product will never fail; the useful signal is whether the vendor explains and fixes problems responsibly.

Also find the export and deletion instructions before committing. Export lets you move to another manager, but NCSC warns that some exports place every password in an unencrypted text file. If you ever export, do it on a trusted updated device, import promptly, verify the result, and securely remove the exposed file and its copies. Do not email it, leave it in Downloads, or store it in an ordinary cloud folder.

Features that matter only if they solve your problem

Breach warnings, secure notes, family plans, account sharing, and passkey support can be useful, but they come after the basics. Prefer a clear sharing tool over sending a password in chat, and check exactly whether removing a person's access also rotates the shared password. For work or school credentials, follow the organization's policy and use its approved manager rather than placing those credentials in a personal vault without permission.

Choose passkeys when an account offers them and your recovery setup is ready; a password manager still helps with the many accounts that require passwords. The winning setup is usually the smallest one that generates unique credentials, fills them on the right sites, works across your devices, protects the vault with MFA, and has a recovery plan you have actually stored.

A fifteen-minute decision, not a feature tournament

Reject any option that misses a device you use, lacks a generator, cannot limit autofill to the saved site, or cannot protect the vault with MFA. For the options left, compare recovery and export instructions in the vendor's own documentation. Then choose the one whose normal save, fill, and unlock flow feels clear enough to use every day.

Migrate gradually. Start with your main email account and other high-value accounts, give each a newly generated unique password, and confirm recovery and MFA before moving on. Do not delete the old manager or any deliberate backup until you have verified the new vault on another device.
